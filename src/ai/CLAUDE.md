# src/ai

AI layers that command the heroes of one side. Each extends `AiLayer`, which implements `AIController` (`tick`, `isWaiting`, `dispose`) from `src/engine/SimulationEngine.ts`, and is attached per match by `UIController.startControllers()`.

| File               | Layer                   | How                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------ | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JevController.ts` | 2, tactical (D6, D21)   | Every 4 s, one request per side to `/api/jev` (dev proxy → TypeSafe) or `/api/snap` (D51). One Choice question per hero over a fixed option list; applies the confident choices and keeps the assessments for the LLM.                                                                                                                                                                             |
| `JevQuestions.ts`  | –                       | What Jev is asked per hero: the option list (what each option is for and not for, the command it runs) and the assessment questions (surrounded, threat, does the order still fit).                                                                                                                                                                                                                |
| `JevSituation.ts`  | –                       | What Jev is told per hero in the state: status, orders, force ratio, nearby enemies, allied heroes, strays, the local map; within `VIEW_RADIUS` (40) the enemy groups (heroes standing together counted as one army, with force ratio and movement since the last request) and the way ahead (D60); and the objective from its side's view. |
| `Detour.ts`         | –                       | D60: the side's cost of tiles near enemy units (`threatCosts`) and the way around them to the LLM's move point (`detourFor`): a move with via points, offered to Jev as `continue_around`: the way around's corners, then all the LLM's remaining via points (corners that do not fit in `MAX_VIA` are left out, those whose loss passes fewest enemies first); offered again unchanged while the way the hero walks still ends with the rest of the LLM's route. |

Notes hero deaths and survival reflexes every step for the next report.                                                                                                                                                                                            |
| `LlmReport.ts`     | –                       | The LLM's report: groups, armies, strays, events, sectors, objective, terrain, with the changes since the last report the LLM saw.                                                                                                                                                                                                                                                                 |
| `LlmReply.ts`      | –                       | Reading the LLM's answer: its JSON, each order checked and turned into a command or rejected with a reason; what the answer cost.                                                                                                                                                                                                                                                                  |
| `AiLayer.ts`       | –                       | Base class of both controllers: the shared lifecycle (interval `tick`, one request at a time, `isWaiting`, `dispose`), the request with its timeout and failure handling (`request`, `tryAgainLater`, `fail`) and the counters the panels read (`exchanges`, `failedRequests`, `lastError`, `failure`, …). What is asked, retries, which failures may pass later and the hints stay in the layers. |
| `AiServer.ts`      | –                       | Where `/api/jev`, `/api/snap` and `/api/llm` are: this site, or the tunnel address and password given once in the demo link (`?ai=…&key=…`, D37; the address is reduced to its origin, `https://` added when missing, `http://` for localhost). Failure details, retry helpers.                                                                                                                    |
| `Models.ts`        | –                       | The models a side can use, one id and label everywhere: Claude aliases (Agent SDK, D44), `openrouter:<id>` for other companies' LLMs (D52, list `OPENROUTER_MODELS`), the tactical model Jev or Snap (D51).                                                                                                                                                                                        |

| `types.ts`         | –                       | Types the layers share: `JevAssessment` (what Jev reports upward), `LlmDecision`, `LlmUsage`. |

| `GameRules.ts`     | –                       | The rulebook for both layers, built from `src/engine/Rules.ts`: the LLM system prompt and Jev's `game_rules` (D26).                                                                                                                                                                                                                                                                                |

## Conventions

- A side is commanded by the LLM alone or by the LLM with a tactical layer, Jev or SubQ Snap (D38, D51; `JevController` with `model: 'snap'` posts to `/api/snap`); a tactical layer alone is not offered. The LLM asks every 15 s (D50).
- Every LLM order carries a reason (D41), kept on the command (`HeroCommand.reason`): Jev gets it as `commander_reason`, in its "continue" option and in its "does the order still fit" question, and follows an order while its reason holds. The reason is logged with the decision and shown per hero in the AI panel (with the hero's current order and its source).
- D60: an LLM move can carry `via` places (at most `MAX_LLM_VIA`), and any LLM order a `fallback` {when, do: retreat | regroup | hold}; a bad one refuses the order. The fallback is a hint: Jev gets it as `commander_fallback` and on the option it names (regroup: `regroup_short` when offered) and judges the condition; the engine ignores it. Jev's own options for the LLM's plan: `continue_around` (the LLM's move by a way around enemies, `Detour.ts`) and `regroup_short` (one stray group, then the LLM's order).
- A Jev answer is stale for a hero whose LLM order changed while the request was open (a new order, not a restatement): its choice was made for the old order (`continue_around` even leads to the old point), so it is not applied (`applied: false`, `stale: true`) and the LLM's latest order runs (D15). The check comes after a choice that is the LLM's (new) order has become "follow the LLM": `continue_llm`, and a choice that equals the LLM's new order, take the LLM's order when they run and are still applied. `regroup_short` is still applied while the LLM's new order is of the same type as the one it was chosen for, and stale when that is now a retreat or hold or another type. A hero no longer `controller === 'ai'` (the user took it over while the request was open) gets no Jev order.
- Only command heroes with `controller === 'ai'` of the controller's own faction.
- Apply decisions only through `engine.issueCommand(hero, command, 'jev' | 'llm')`.
- Jev may only return options we define; the LLM's free-form reply must be validated (hero exists, sector valid, target alive; a hero number is an integer or a string of digits, never coerced from `true`, `[1]` or `"1e0"`; `LlmReply.ts`). Invalid orders are logged and skipped, never guessed.
- Keep inputs small and within scope (D16): Jev sees one hero's surroundings, the LLM the whole map. Jev also sees where the other heroes of its side are (distance, direction, HP, soldiers, enemies near them) and can bring a hero to one of them step by step (`approach_hero_<n>`, a short move toward its current place, offered when it is more than 8 tiles away), e.g. when the LLM's reason says to join or support it.
- Code computes, the AI judges (R5): pass computed values (force ratios, group stats, recent losses), never raw unit lists or screenshots.
- Values every hero of a Jev request shares (group stats, stray clusters) are computed once per request, not per hero; `tick()` runs every simulation step, so it allocates nothing in the usual case.
- A change to what the layers are sent must be deliberate: `tests/smoke/prompts.ts` prints every rulebook and request, so a refactor can be checked to leave them character-identical.
- The rulebook states the game's mechanics only, never strategy advice (D43): the experiments measure the AI's own judgement.
- Jev has no memory: every request carries `game_rules`. The LLM gets the rulebook once per match as its system prompt.
- Log every decision with its response time (`decisions`); these feed the latency experiments. Every request is also kept with its answer or error (`exchanges`, `Exchange.ts`) for the AI panel's request log and the match log; the LLM's rulebook is kept once (`system`), not per request.
- Never start a new request while one is open; count it as skipped (Q7).
- Every request has a timeout (LLM 120 s, Jev 30 s, `timeoutMs`, values in `Limits.ts`); a request without an answer counts as a failure, so paused AI timing can never freeze the battle. `pending` is set only once the request is built, and a throw while building it stops the layer with the error as its `failure` (`AiLayer.tick`); a stopped LLM layer notes no more events. A throw while an answer is applied stops the layer too (`error while applying the answer: …`, also on the exchange), never counted as a lost connection that may pass.
- Failed requests (pass 4, following TypeSafe's and Anthropic's guidance): Jev retries 408, 429, 5xx and lost connections twice within the request, after 0.5 s and 1 s with up to 25% jitter (from `crypto`) and honouring `Retry-After`, as TypeSafe's own SDKs do (`fetchWithRetries`); a try is skipped when it would not fit in the request's time budget after the wait (the last try's failure is then returned), and the deployed proxy gives up on TypeSafe after 14 s (`api/jev.ts`, passing `Retry-After`/`retry-after-ms` on), so a silent TypeSafe ends as a 504 that may pass later, not as the 30 s timeout; the LLM does not, since the Claude CLI behind the endpoint already retries up to 10 times. A request that still fails but may pass later (the LLM endpoint's `retryable`, 408/429/5xx, a lost connection) is counted in `failedRequests` and shown as `lastError`, and the layer asks again at its next decision; `FAILURES_IN_A_ROW` (3) such failures stop it. 401, 403, 404/405, 413, 422, a refused AI password, a plan or budget limit and a timeout stop it at once.
- Answers are recorded with what the services report: Jev's version (`model`, e.g. `jev-1.13.0`; the request asks for `jev-latest`), its input tokens and the number of tries; the LLM's estimated cost, tokens, API time and full model ids (`usage`). Jev's choice probabilities stay in the request log and the match log.
- Controllers implement `dispose()`: the engine disposes them on restart and when they are replaced, which aborts the open request and drops a late answer, so it cannot reach the heroes of the next match. One malformed entry in the LLM's `orders` is skipped with a reason, not treated as a failure.
- On failure, stop the layer and set `failure` (shown in the AI panel and written to the match log) with the server's own error text when it gives one and a hint on what to do (e.g. a tunnel or proxy status such as Cloudflare's 530 means the AI server cannot be reached); hand heroes to the rule layer only if no other AI layer is attached (`fallbackToRules`). The layers of a side are the ones attached to the engine (`getControllers`): when the LLM stops, its tactical layer stops with it and drops its open request (D38: a tactical layer alone is not offered); when the tactical layer stops, the LLM goes on alone; when no layer of the side is left, its heroes go to the rule layer.
- Never use `Math.random`: the simulation draws from it, so an AI layer that did would change the battle it is playing (the match id uses `crypto`).
- `window.ai.west` / `window.ai.east` (`{ jev, llm }`) expose the running controllers for inspection in the browser console.
