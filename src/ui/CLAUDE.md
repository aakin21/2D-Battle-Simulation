## Conventions

- Hero orders from the user go through `engine.issueCommand(hero, command, 'user')`; right-click commands the selected friendly hero (or the first one), and only heroes the user controls (never AI heroes in Agent vs Agent).
- After every `engine.restart()`, call `UIController.startControllers()`: restart clears the AI layers.
- Settings saved in local storage are per-browser conveniences only (speed, debug, effects, bars, sound, the hints seen); reads and writes are wrapped in try/catch, since storage can be unavailable.
- Screens: the front end (`#main-menu`, full screen, the HUD hidden: `body.front-open`) shows the title screen, Match setup or the Sandbox; the pause menu (`#pause-menu`) is a small panel over the run or replay, the HUD in view. At page load the title screen shows (a returning visitor too), or the screen the user left for openrouter.ai. Esc, Menu and a result card's Menu open the pause menu over a run or a replay (with nothing behind: the title screen). Esc goes back one screen (Match setup / Sandbox → title screen, or → the pause menu they were opened from; the title screen → the pause menu it was opened from; the pause menu → Continue); a dialog or the Controls screen takes Esc first. Continue resumes the run or replay only if it was running when a menu opened. New battle opens Match setup (or the Sandbox after a Sandbox run) with the current choices; Start there replaces the run. Focus goes to each screen's main action (title: Continue when shown, else Play; Match setup and the Sandbox: Start; pause: Continue).
- The attract battle never touches the page's simulation: it plays a recording (no engine, no battlefield of its own, no `Math.random`) and is disposed before a run starts or a replay is shown (`tests/smoke/frontend.sh` hashes a run started with and without it, counts the page's `Math.random` draws over its loops and checks its module graph). The page's own frame loop does not run while the front end covers the page. A new recording: `attract-record.ts` in `../tests/smoke/` (its README), never a battle with AI layers.
- State hooks for styles and motion (no inline styles, layout by CSS; menu.css lists them): `body[data-screen]`, `#main-menu[data-screen][data-attract]`, `#title-screen[data-replays][data-run-behind]`, `#connections[data-server][data-own][data-openrouter][data-bridge]` (the wrapper of the AI connections cards; `data-bridge` also `invite`), `.side-card[data-commander][data-way][data-ready]`, `#sandbox-screen[data-tab]`, `#pause-menu[data-run]`, `.screen.enter`, `.front.fade-in`.
- The hints read the heroes and the camera only: they never change the simulation, never pause it, never take focus, draw nothing on the canvas and use no `Math.random`. They show only when nothing covers the battlefield (no front end, pause menu, Controls or loading screen, no result card) and stay off the hero they point at.
- Motion follows `prefers-reduced-motion` (theme.css cuts animations and transitions; the hints then hide at once; the attract battle is one still frame of its recording).
- Game shortcuts (Space, +/−, R) are ignored while the front end, the pause menu, a dialog, the Controls screen or the loading screen is shown. While the match intro (the loading screen) is shown Enter and Space start the battle, Tab keeps the focus on it and every other key is ignored, Esc too. While a replay is watched, Space, +/− and R act on the replay. Keys with Cmd or Ctrl are left to the browser (reload, page zoom), and a held key acts once, except +/−. Typing in a text field (a text-like `<input>`, a `<textarea>`, a contenteditable element) is never a shortcut: its character keys stay with the field (Esc and Enter still reach the page).
- A run stopped by a simulation error (`engine.setOnError`) shows a "Simulation stopped" card in place of the result; it cannot be resumed, only restarted, and the match log records the error.
- A saved map that is missing or cannot be read stops Start with a message (it is never replaced by a random map), and saving under an existing name asks first.
- New menu options become fields of `SimConfig` (`src/types/types.ts`) rather than state kept in the UI.
- Connecting OpenRouter reloads the page (openrouter.ai and back): a run behind the menu is asked about first, and the menu's choices and screen are kept in sessionStorage for the trip only and put back on return (only known controls and values they offer; a way counts as the user's only when it is offered here; the title screen when none came back).
- "This page has an AI server of its own" is one rule, `ownAiServer()` (Connections.ts): `npm run dev` (`import.meta.env.DEV` with this site's endpoints) or an AI server elsewhere given in the demo link (`?ai=`, a tunnel, D37). The AI bridge on this computer is not the page's own: it is connected on its card (or Connect… in Match setup; at page load without a click when the page came with its address and the browser's permission is granted) and what it runs comes from its status (`GET /api/bridge`, 1.1.0: Claude, Codex, Gemini, local models, OpenRouter on its key, its commands; a 1.0.0 bridge's missing fields are "not said"). The page's own AI server answers the same status (the dev server, `bridge: false`): Match setup asks it once per page load when it first opens (`ServerStatus.ts`, no user gesture: this site or the tunnel, never a server on this computer); until it answers, or when it cannot, the AI server's list is what it always offered. An LLM side's ways: the AI server (only with one), OpenRouter (the browser's own connection: OpenRouter's list), This computer (only without an own AI server). On the AI server and This computer the list is what the status says it runs (OpenRouter's list only with its key and no browser connection), then what it cannot run, disabled, with why: the status's own reason for Codex, `GEMINI_API_KEY` for Gemini, "an older version" for what a 1.0.0 bridge does not say. OpenRouter models go straight from the browser whenever it is connected (LlmController), so they are listed only under OpenRouter then. A way is preselected only when it can run now (the first ready one, or none), and a model only when it can run; a way the user chose stays chosen, with Connect… while it cannot run. Start refuses, next to the side, with what to do: no way; a way not connected or still connecting; a bridge this page has not reached yet (the first request to it comes from a click); a bridge or an AI server that runs nothing here (why, per way); a typed OpenRouter id, local, Codex or Gemini name that cannot be one; LLM + Jev / LLM + Snap while the page's AI server is a bridge (it has no Jev or Snap). Claude on the bridge runs on the Claude Code sign-in of the person running it, or its `ANTHROPIC_API_KEY` (`claude: true` either way); the menu says only that it uses the Claude Code sign-in on that computer and gives no legal advice (the README has the terms' sentence). The whole dev server on this computer is opened as this site (http://localhost:5173), not as a bridge: the dev server's status says `bridge: false`, so This computer never takes it for one.
- Match setup and the Sandbox fit the window: their body scrolls when taller, and the bar with Back and Start stays in view; nothing scrolls sideways (the bridge's long commands scroll in their own box). Three columns West | Battle | East from 900 px, the sides above the battle below that, one column below 640 px.
