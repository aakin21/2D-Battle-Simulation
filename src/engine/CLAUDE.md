# src/engine

The simulation itself. `SimulationEngine` owns the loop; the other files are parts it uses.

| File                  | Role                                                                                                                                                                                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SimulationEngine.ts` | Run lifecycle (start, pause, speed, restart, errors), the fixed-step loop and the step: AI ticks → rule heroes → hero commands → hero stand → courage → behavior → movement → separation → rest → combat → objectives → deaths → match end → waves. The loop runs `frame(t)` (private): the steps the frame's time asks for, then the drawing, without asking for the next frame. `step()` (public) is one step of `SIM_STEP` as the loop runs it; headless runs (the smoke tests, experiments) call it. Nothing outside the engine runs its frames (the title screen's battle is a recording, `src/ui/Attract.ts`) |
| `Soldiers.ts`         | Soldiers (`isSoldier`), the hero they follow (`findLeader`), courage (D14), followers per hero and how close to it they stop                                                                                                                                                            |
| `Behavior.ts`         | Each unit's state per frame: hero reflex, flight on low courage (D57), rest (D45), breaking off (D27), attack in range                                                                                                                                                                  |
| `Movement.ts`         | Movement per frame: flight, wave berserkers, heroes to their task or stand point, soldiers to their hero's, along A\* paths                                                                                                                                                             |
| `Combat.ts`           | Rest healing, combat (damage summed, then dealt), removal of the dead                                                                                                                                                                                                                   |
| `HeroCommands.ts`     | Command interface (D20): `issue()` stores an order, `applyAll()` turns orders into task points each frame; a move's via points are walked in order, progress kept as the points the hero reached and when (D60); `effective()` is the order a command runs now (Jev's "follow the LLM", or a `regroupOne` whose group is gone, run the LLM's latest order), for the task point and D48; stray groups are cached for 0.5 s, cleared on restart (`reset()`)                                                                                                                                                                                        |
| `HeroPosition.ts`     | D48: a hero with enemies near stands behind its soldiers (`standPoint`); its group goes on to the order's point                                                                                                                                                                         |
| `HeroReflex.ts`       | Hero survival reflex and retreat movement (D18, D45, D47)                                                                                                                                                                                                                               |
| `RuleHeroes.ts`       | Rule-based heroes (no AI): attack when an enemy is in sight, otherwise take a control point or attack the enemy base (D30), otherwise patrol                                                                                                                                            |
| `Objectives.ts`       | Battle objectives (D30): control points scored by majority, bases that units attack, match end by objective or time                                                                                                                                                                     |
| `Strays.ts`           | Stray soldiers (D28): soldiers with no hero in sight, grouped into clusters for the AI and for regroup orders (D40)                                                                                                                                                                     |
| `ClassicWaves.ts`     | Classic mode (D19): berserker waves from the map edges, and the path of a wave berserker (chase its target or patrol with its group). Battle mode never runs it |
| `GroupPatrol.ts`      | Random patrol destinations (classic berserker waves and rule heroes)                                                                                                                                                                                                                    |
| `Separation.ts`       | Battle mode: units take up room, pushing each other apart (D53), never into a mountain buffer or another walkable region; a hero is not pushed by its own side; a unit marching with no enemy within 20 tiles pushes its own side a tenth as hard (D59)                                 |
| `UnitHelpers.ts`      | Shared helpers: nearest enemy, attack target (D55), effective sight, terrain speed, stepping (`canStep`, `stepToward`, `fleeWayOpen`), reachable tiles                                                                                                                                  |
| `Pathfinder.ts`       | A\* with a binary heap and path smoothing; mountains and their neighbours are blocked (`isBlocked`); walkable regions (`labelRegions`); an optional extra cost per tile and `findPathAvoiding` for the tactical layer's way around enemies (D60; the simulation never passes one)                                                                                                                                                  |
| `SpatialGrid.ts`      | Spatial hash for neighbour queries; a finer grid with per-cell faction counts makes courage counts and nearest-enemy search fast in crowds with identical results (D31); a tile index, rebuilt after units move, gives separation the same neighbours in the same order as a plain scan |
| `BerserkerPool.ts`    | Object pool for classic wave berserkers: starts empty, used only where waves run (classic mode outside the stress test) |
| `Sides.ts`            | The two sides (West = friendly, East = enemy): `opponent()` and `sideName()`                                                                                                                                                                                                            |
| `Sectors.ts`          | 10×10 sector grid (A1–J10) and 3×3 sub-sectors (e.g. `D4-NE`) used to describe locations to the AI (D17, D26)                                                                                                                                                                           |
| `Rules.ts`            | The numbers that define behavior (the time step `SIM_STEP`, combat, courage and flight, charisma, rest, hero reflex, retreat, room per unit, hero behind its soldiers, objectives)                                                                                                                                |

## Conventions

- Order of a step matters: AI ticks and command application run before behavior and movement.
- The loop has a fixed time step (P9; Glenn Fiedler's "Fix Your Timestep"): every step advances the battle by exactly `SIM_STEP` (1/60 s, `Rules.ts`), whatever the frame rate or the speed. Each frame adds the real time since the last frame (at most `MAX_FRAME_SECONDS`, 0.1 s; never negative) times the speed to an accumulator and runs one step per whole step it holds, at most `MAX_STEPS_PER_FRAME` (12: 4x down to 20 frames a second); the remainder waits for the next frame. A higher speed runs more steps per frame, never a longer step, so the same seed plays the same battle at every speed and on every machine; a machine too slow for the speed asked runs the game slower instead. The accumulator starts at a quarter step (`ACCUMULATOR_START`), so 60 Hz frames run exactly one step each despite jitter. Time owed when the steps stop early (the cap; the match ended; the run failed; in paused AI timing a layer began waiting in the step just run, D4) is dropped, never caught up later. A paused run (or one waiting for an AI answer) takes no time in and keeps its remainder. The first frame after `start()` (a restart, the menu closing over the run) only sets the time base; a frame that began before the last one counts nothing. Drawing runs once per frame, after the steps.
- The clock: `step()` sets `elapsedTime` to the step grid (k / 60 s, so 480 s is exactly 28 800 steps); never add to it by hand in new code. Every time in `Rules.ts` is a whole number of steps. The match end is checked at the end of a step: the step that ends at the time limit is the last (nothing scores or acts past it), and `MatchResult.time` is the clock the match stops at.
- `onStep` (the replay recorder) runs once per step, the AI ticks too; whatever happens per frame (drawing, effects, battle sound) gets the frame's real time and sees the steps of a frame together.
- An exception in a simulation step stops the run (paused, `getError()`, `setOnError`) instead of the loop; the clock stays where the failing step began, and `resume()` refuses until a restart. A drawing error is logged once and the run goes on.
- `issueCommand` ignores a move or hold whose point is not a finite number.
- `issue` compares orders by what they run: Jev's "follow the LLM" (`continueLlm`) runs the LLM's latest order, so the LLM restating that order, or Jev following the order already running, is a repeat (no new point, age kept, no break-off, the reflex goes on). An LLM order that restates Jev's takes over its point. The LLM restating its own order while another one runs (Jev's) takes over again (D15) but is no new order: it keeps its age (`lastLlmTime`) and its via progress, and takes the new reason and fallback. A retreat's `to`, like move and hold points, must be finite or the order is ignored.
- A move order can carry via points (D60, at most `MAX_VIA`; the LLM gives at most `MAX_LLM_VIA`): the hero's task point is the next one not reached, so its soldiers walk the same route. A point counts as reached within 5 tiles of the hero, or of its stand point plus `HERO_BEHIND_TILES` while it stands behind its soldiers; one in another walkable region is passed over. A route goes on from the points reached since its order was given (`viaReached`, `orderTime`; an LLM order counts from `lastLlmTime`): the same order restated, or Jev's "follow the LLM" after a detour, goes on; a new order starts over. Only reached points that can still count are kept (since the running order, or since the LLM's order if on its route; at most 64), so long detours do not push out the LLM route's progress. `regroupOne` (Jev only) collects the stray group near its point, then runs the LLM's latest order (`effective()`: where the hero stands, D48, follows that order too).
- A retreat order falls back from the enemies within `RETREAT_SCAN` (20) tiles as far as the hero walks in `RETREAT_SECONDS` (5: one Jev interval plus its answer time, about 10 tiles), worked out once when given; repeated once the hero has reached that point (and is not fleeing by its reflex), it falls back further from the enemies near it then (D39); a regroup order collects stray groups one after another, since its target is re-evaluated as groups join (D40).
- An attack or lead order goes for the nearest enemy within the hero's sight (terrain included), re-evaluated every frame; with none in sight the hero stays where it is. Once a hero has gone for an enemy it keeps after it out of sight too, until it dies or is more than `ATTACK_CHASE_TILES` (30) away (`attackTarget`); rule heroes stay on attack meanwhile. A control point is taken by the side that has had the most units near it for `CONTROL_CAPTURE_SECONDS` (3) in a row, and scores while that side keeps the majority; a control match lasts `CONTROL_TIME_LIMIT` (480 s) and is decided on whole points alone (`wholePoints`, as shown; a score within 1e-6 below a whole point counts as it, the rounding error of summing 1/60 s steps), equal points are a draw; the other modes then go by total HP left.
- Unit states: `IDLE → ATTACK → FLEE → REST`. Soldiers flee on low courage; heroes "flee" only through the reflex (D18), which a user, Jev or LLM order can end. The reflex starts when a hero is hurt (below 50% HP) and more enemies than allies are in its sight, or when at least 5 enemies outnumber its allies 2 to 1 (D45). Below `HERO_CRITICAL_HP_RATIO` (25%) a hero flees from any enemy in sight and no order ends that flight; an order that ends a flight keeps the reflex off until the hero's sight is clear or for `HERO_REFLEX_OFF_SECONDS` (5 s), whichever comes first (D47). In battle mode a hero below `HERO_REST_TRIGGER_HP` (100) rests whenever it stands still with no enemy in sight; a hero of the user, Jev or the LLM stops resting as soon as an order sends it somewhere (D45).
- In battle mode berserkers are soldiers (`isSoldier`) and follow the nearest hero of their side within its sight (`findLeader`). A soldier with no such hero stays where it is, also when its side has no heroes left (D35, D42).
- Rule numbers live in `Rules.ts`. The AI rulebook (`src/ai/GameRules.ts`) is built from them, so change a rule there and the prompts follow. Other tuning constants are named at the top of the file that uses them.
- Pure helpers take the `StateManager` as their first argument instead of reaching into the engine.
- Classic-mode code paths (waves, berserker chase/patrol) must not change behavior; battle-only logic is guarded by `battleMode`.
- Neighbour queries must return exactly what a plain scan returns (D31). Courage uses `countByFactionInRadius`, nearest enemy uses `nearestEnemyInRadius` with a full-scan fallback on exact ties (`nearestEnemyByScan`), separation uses `unitsInRadiusInScanOrder`, and separation and breaking off check for an enemy with `hasEnemyInRadius` (the units `forEachInRadius` visits, in its order, so the pushes add up the same). Changes here must leave the simulation identical: `same.ts` (diff against the base output) and the `strays-equiv` / `anywhere-equiv` smoke tests (`../tests/smoke/`).
