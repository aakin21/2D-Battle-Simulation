# server

Code that runs inside the Vite dev server (Node), never in the browser. Loaded from `vite.config.ts`.

| File           | Role                                                                                                                                                                                                                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aiAccess.ts`  | Guard for `/api/*` (D37): CORS for the online demo's origin; requests that do not come from localhost (i.e. through a tunnel) need `AI_PASSWORD` in the `x-ai-key` header. Requests that carry another website's `Origin` are refused (403) even on localhost: any page open in the browser can send a simple POST there. Refusals carry `x-ai-access: denied`. |
| `llmPlugin.ts` | `POST /api/llm`: one persistent, lean Claude Agent SDK session per side (D10, D22). A new `matchId` or model starts a new session. The system prompt and the model (`haiku` / `sonnet` / `opus`, chosen per side in the menu, D29) come with each request; each alias runs a pinned model id of the 5.5 generation (`MODEL_IDS`, D44), never the CLI's own alias.                                                                                                      |

The decision-model proxies are configured directly in `vite.config.ts`: `/api/jev` (TypeSafe, `TYPESAFE_API_KEY`) and `/api/snap` (SubQ Snap, `SUBQ_API_KEY`, D51) both go to `/v1/systemone` and add their key from `.env.local` (D7, P1). They forward only `Content-Type`, `Content-Length`/`Transfer-Encoding`, `Accept` and the server's own `Authorization`: the browser's `Origin`, the AI password (`x-ai-key`), cookies, the referrer and any `Authorization` from the browser stay on the dev server. The service's `Set-Cookie` and `Access-Control-*` headers are not passed back, so the guard's CORS headers are the ones the browser sees.

A model `openrouter:<id>` (D52) runs that model through OpenRouter's chat API with `OPENROUTER_API_KEY`: the session keeps the match's messages and sends them all with each request; HTTP 400–404 (wrong key, no credits, unknown model) are not retryable; cost comes from OpenRouter's `usage.cost`. An unknown model name is refused with 400.

## Conventions

- Uses the developer's own Claude login (personal, local use; D9, D10). Final experiments switch to the Claude API.
- Keep sessions lean: custom system prompt, no tools, no project settings, auto memory off. The default Claude Code setup makes the model answer as a coding assistant (R2).
- The system prompt defines the reply format; the browser validates every reply anyway.
- Not part of `npm run build`: the static build has no `/api/*` endpoints. The online demo reaches them through a tunnel to the author's computer (D37); `vite.config.ts` allows the tunnel host names (`allowedHosts`).
- `aiAccess` must stay the first plugin, so its check runs before the Jev proxy and the LLM endpoint.
- `/api/llm` is reachable through the tunnel, so it is bounded: bodies over 1 MB (counted in bytes, refused at once when Content-Length says so) get 413 and a body that stalls for 30 s gets 408, the answer sent before the connection is closed; `side` must be `west` or `east` (one session each), a body that is not JSON or whose `side`, `matchId`, `system` and `prompt` are not text gets 400, and an answer that has not come after 110 s (below the browser's 120 s) fails with the session closed (the next request opens a fresh one). A session that is closed (new match or model) or whose SDK stream ends fails its waiting requests at once, and an ended session is replaced by the next request.
- An SDK result with `is_error` (an API error after the CLI's own retries, e.g. overloaded, rate limited, a plan limit, an expired login) or an error subtype is an error, never the model's reply. It is answered with 500, `{ error, retryable }`: plan, budget and login problems are not retryable. Such an error leaves the session open, so the match keeps its conversation.
- The dev server's output logs, per side, the model each session actually runs, every retry the Claude CLI makes on its own (status, delay) and each answer's time, and every failed request; nothing secret is logged.
- Each answer carries what it cost: `costUsd` (this answer, from the SDK's running total), input, output and cached tokens, `apiMs` and the full `modelIds` (estimates, for Q11). A session stops at `LLM_MAX_BUDGET_USD` (default 5) of estimated spend.
- `LLM_MODEL` and `LLM_MAX_BUDGET_USD` are read from the `env` Vite loads from `.env.local` (passed to `llmPlugin(env)`), falling back to a shell export.
