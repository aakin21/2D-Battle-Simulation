# server

Code that runs inside the Vite dev server (Node), never in the browser. Loaded from `vite.config.ts`.

| File           | Role                                                                                                                                                                                                                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aiAccess.ts`  | Guard for `/api/*` (D37): CORS for the online demo's origin; requests that do not come from localhost (i.e. through a tunnel) need `AI_PASSWORD` in the `x-ai-key` header. Requests that carry another website's `Origin` are refused (403) even on localhost: any page open in the browser can send a simple POST there. Refusals carry `x-ai-access: denied` and `Connection: close`: the request's body is not read, and its connection is closed after the answer (destroyed 1 s later if the other side goes on sending) instead of staying open until Node's own timeouts. |
| `llmPlugin.ts` | `POST /api/llm`: one persistent, lean Claude Agent SDK session per side (D10, D22). A new `matchId` or model starts a new session. The system prompt and the model (`haiku` / `sonnet` / `opus`, chosen per side in the menu, D29) come with each request; each alias runs a pinned model id of the 5.5 generation (`MODEL_IDS`, D44), never the CLI's own alias. `openrouter:<id>` and `local:<name>` go to an OpenAI-compatible chat API instead (`ChatSession`; what differs between the two is in `ChatApi`). |

The decision-model proxies are configured directly in `vite.config.ts`: `/api/jev` (TypeSafe, `TYPESAFE_API_KEY`) and `/api/snap` (SubQ Snap, `SUBQ_API_KEY`, D51) both go to `/v1/systemone` and add their key from `.env.local` (D7, P1). They forward only `Content-Type`, `Content-Length`/`Transfer-Encoding`, `Accept` and the server's own `Authorization`: the browser's `Origin`, the AI password (`x-ai-key`), cookies, the referrer and any `Authorization` from the browser stay on the dev server. The allowlist is applied to the incoming request's headers on the proxy's `start` event, before they are copied (the proxy skips its `proxyReq` event for a request with an `Expect` header), and checked again on `proxyReq`. Only POST is proxied: another method gets 405 (the `decision-proxy-methods` plugin, after the guard). The service's `Set-Cookie`, `Access-Control-*`, `Location` and `Vary` headers are not passed back, so the guard's CORS headers are the ones the browser sees, and a redirect from the service becomes 502. A service that has not answered after `JEV_PROXY_TIMEOUT_MS` (14 s, `src/ai/Limits.ts`; `api/jev.ts` keeps the same literal) gets 504 and its request is closed, an answer whose body stalls is cut at that time, and an unreachable service gets 502: the browser retries these within its 30 s.

A model `openrouter:<id>` (D52) runs that model through OpenRouter's chat API with `OPENROUTER_API_KEY`: the session keeps the match's messages and sends them all with each request; HTTP 400–404 (wrong key, no credits, unknown model) are not retryable; cost comes from OpenRouter's `usage.cost`. An unknown model name is refused with 400. Both chat APIs (`ChatSession`) never follow a redirect: a 3xx is an error, not retryable (the rulebook and the report would go to whatever address it names). The service's own error text is cut to 300 characters in messages and the log. A key (`OPENROUTER_API_KEY`, `LOCAL_LLM_KEY`) is trimmed, and one with anything but printable ASCII (a line break, a pasted curly quote) is answered with 500, not retryable, before anything is sent: fetch would refuse it with an error that holds the whole header; the key is masked in fetch's own error text anyway. A session closed (new match or model) while an answer is read fails that request with "session was closed".

A model `local:<name>` runs `<name>` on the user's own computer (Ollama, LM Studio, llama.cpp) or any other OpenAI-compatible chat API. `LOCAL_LLM_URL` is the API's base, `<base>/chat/completions` is called (default Ollama's `http://localhost:11434/v1`; an address that already ends in `/chat/completions` is used as it is; http or https only; spaces around it, or only spaces, ignored), `LOCAL_LLM_KEY` an optional Bearer key (only spaces: none), `LOCAL_LLM_HISTORY_TURNS` how many earlier reports and answers each request carries again besides the rulebook and the new report (a plain whole number, default 3, `0` none: a local model's context window is small), with `stream: false`. The settings are read once when the dev server starts, from `.env.local` only, never from a request: the endpoint is reachable through the tunnel. The model name (checked in `Models.ts`) goes into the request's body and into the server's messages and log, never into the address. At start the log warns once about a `LOCAL_LLM_HISTORY_TURNS` that is not a whole number (3 is used) and about a key that would go over plain `http://` to another computer. A wrong `LOCAL_LLM_URL` (not http(s), a user name or password in it) or key is answered with 500, not retryable, saying what to fix. The answer: a reasoning model's thinking (`<think>` or `<thinking>`, any case, attributes) is removed: the answer is what follows the last closing tag, unless that has no `{` (an answer that only mentions the tag keeps its text); an opening tag that is never closed is dropped alone (`LlmReply` reads the JSON from the text's first `{`, which may be in the thinking). Content in parts is joined. An answer that is empty (a reasoning model may have used its whole output on thinking), cut off (`finish_reason: "length"`) or over 200 KB of text is an error that may pass, never a 200, and is not sent again: the browser would read it as no orders and go on, while failures are counted and three in a row stop the layer. OpenRouter's answers are taken as they come. Cost comes from `usage.cost` when the server sends a number (a paid API might) and counts towards `LLM_MAX_BUDGET_USD` as for OpenRouter; Ollama sends none, so no cost and no budget stop. Tokens from `usage` when the server sends them. Errors say what to do: the server unreachable (retryable; is it running, `LOCAL_LLM_URL`), 404 or a missing model (the server does not know the model, with Ollama `ollama pull <name>`, or `LOCAL_LLM_URL` is not its OpenAI-compatible address), 401/403 (`LOCAL_LLM_KEY`), a redirect (set `LOCAL_LLM_URL` to the final address); as for OpenRouter, 400–404 are not retryable.

## Conventions

- Uses the developer's own Claude login (personal, local use; D9, D10). Final experiments switch to the Claude API.
- Keep sessions lean: custom system prompt, no tools, no project settings, auto memory off. The default Claude Code setup makes the model answer as a coding assistant (R2).
- The system prompt defines the reply format; the browser validates every reply anyway.
- Not part of `npm run build`: the static build has no `/api/*` endpoints. The online demo reaches them through a tunnel to the author's computer (D37); `vite.config.ts` allows the tunnel host names (`allowedHosts`).
- `aiAccess` must stay the first plugin, so its check runs before the Jev proxy and the LLM endpoint.
- `/api/llm` is reachable through the tunnel, so it is bounded: bodies over 1 MB (counted in bytes, refused at once when Content-Length says so) get 413 and a body that stalls for 30 s gets 408, the answer sent before the connection is closed; `side` must be `west` or `east` (one session each), a body that is not JSON or whose `side`, `matchId`, `system` and `prompt` are not text gets 400, and an answer that has not come after 110 s (below the browser's 120 s) fails with the session closed (the next request opens a fresh one). A session that is closed (new match or model) or whose SDK stream ends fails its waiting requests at once, and an ended session is replaced by the next request.
- An SDK result with `is_error` (an API error after the CLI's own retries, e.g. overloaded, rate limited, a plan limit, an expired login) or an error subtype is an error, never the model's reply. It is answered with 500, `{ error, retryable }`: plan, budget and login problems are not retryable. Such an error leaves the session open, so the match keeps its conversation.
- The dev server's output logs, per side, the model each session actually runs, every retry the Claude CLI makes on its own (status, delay) and each answer's time, and every failed request; nothing secret is logged.
- Each answer carries what it cost: `costUsd` (this answer: from the SDK's running total, or a chat API's `usage.cost`; null when the service reports none, as a local server usually does), input, output and cached tokens, `apiMs` and the full `modelIds` (estimates, for Q11). A session stops at `LLM_MAX_BUDGET_USD` (default 5) of estimated spend; a service that reports no cost never reaches it.
- `LLM_MODEL`, `LLM_MAX_BUDGET_USD`, `OPENROUTER_API_KEY` and `LOCAL_LLM_URL` / `LOCAL_LLM_KEY` / `LOCAL_LLM_HISTORY_TURNS` are read from the `env` Vite loads from `.env.local` (passed to `llmPlugin(env)`), falling back to a shell export.
- `/api/llm` reads at most 8 request bodies at once (more get 503 with `Retry-After: 5`); a browser that closes its request is not waited for (the session and its conversation stay, the late answer is dropped); two matches alternating on one side are logged, at most once a minute per side.
